# 统一线程助手改造方案 + 东港/贝斯美问答样例

## Summary
- 建议把现有系统从“录音任务专用线程”升级为“长期工作线程 + 任务子图”的 LangGraph 标准形态：线程持续存在，录音流程只是其中一个 `subgraph`，任务完成后线程自动切到 `query_mode`，新线程也允许直接发起查询。
- 第一阶段不破坏现有录音主链路，只新增只读查询能力。这样既能保住“上传录音 -> 澄清 -> 分析 -> 画像 -> 商机确认”的稳定性，也能在任务完成后继续问“东港预算多少”“贝斯美当前阶段是什么”等问题。
- 查询实现建议采用“结构化精确查询 + 图关系查询 + 文档检索 + 向量召回”的融合策略，而不是只靠 LLM 记忆或只靠全文搜索。

## Key Architecture Changes
- 根图改为 `assistant_thread_graph`，LangGraph 的 `thread_id` 绑定 `chat_thread.id`；录音流程整体下沉为 `recording_task_subgraph`。
- 线程状态最少包含：`active_mode`、`active_task_id`、`focus_customer_id`、`focus_visit_record_id`、`focus_opportunity_id`、`thread_summary`、`pending_interrupt`。
- 新增 `crm_query_agent` 只读子图，负责查客户、查拜访、查商机、查产物、解释阶段、总结上下文。
- `POST /api/chat/threads/:threadId/messages` 永远把 turn 送入根图，不再在 Express 层直接拒绝“非录音类输入”。
- `meeting-viewer` 回调改为 thread 级事件恢复，而不是只恢复 task 级图。
- 回答契约固定为：`直接答案 + 证据对象 + 未知项/待补信息 + confidence`。对“预算未知”这种问题，必须返回“不知道，但当前只确认 X”。

## Retrieval And Reasoning Strategy
- `SQLite / chat.db`：查线程、任务、消息、task status、已保存的商机金额、产物索引、发言人画像结果。
- `MongoDB`：查客户、联系人、拜访记录、商机、报价等当前业务对象的结构化字段。适合精确问题，如“这个客户有几条商机”“最近一次拜访是哪条”。
- `Neo4j`：查客户-拜访-联系人-商机关系链。适合关系问题，如“谁是关键人”“这条商机关联了哪些联系人”“这个客户有哪些历史拜访”。
- `文件/Markdown/听悟 JSON`：查 `company research`、`信息化评估.md`、`summarization.json`、`meetingAssistance.json`、`autoChapters.json`。适合事实问答、摘要、行动项、章节重点。
- `Chroma / 向量检索`：处理自然语言改写、模糊提问、相似案例召回，如“有没有和东港类似的固定资产项目”“贝斯美这种客户的典型推进策略是什么”。
- `融合策略`：
  1. 先做实体识别：线程焦点客户 > 精确匹配 > 别名映射 > 模糊匹配。
  2. 再做问题分类：结构化字段、关系问题、文档事实、语义相似、缺口判断。
  3. 工具并行取数后统一归一。
  4. 有冲突时以结构化对象和最新 task 记录优先，文档内容作为解释层。
  5. 查不到就显式返回“当前资料未确认”，不允许编造。

## Donggang Sample Questions
说明：这些问题主要基于东港当前录音任务、经营建议和听悟结果，适合“任务完成后的延伸追问”。

1. 问：东港这次项目的核心问题是什么？
预期：核心问题是固定资产账实不符，客户希望强化固定资产管理模块，实现账实相符、便捷盘点、二维码追踪和全生命周期管理。
实现：优先读取听悟 `summarization.json` 与 `meetingAssistance.json`，再用拜访记录摘要做二次归纳；这是“文档事实 + 摘要抽取”，不是图推理。

2. 问：东港当前推荐的总体方案是什么？
预期：推荐采用“ES 财务端 + 云之家业务端”的前后端结合方案，ES 负责采购入库、资产卡片、折旧摊销，云之家负责领用、调拨、盘点、维修、报废等业务动作并回传状态。
实现：主要查听悟摘要与章节总结，必要时回查拜访 markdown；这是“文档检索 + 结构化摘要”，不依赖向量。

3. 问：东港项目现在处于什么阶段？
预期：处于方案评估与供应商筛选阶段，而且是关键窗口期。
实现：优先查经营建议结果或 `visit_record_analyze` 输出；这是 Mongo/能力输出的结构化字段精确查询。

4. 问：东港最关键的客户联系人是谁？
预期：当前最关键联系人是信息部李毅，影响力高、态度谨慎，是主要技术与信任障碍点。
实现：先查 `meeting_profile_results` 和联系人画像，再经 Neo4j 或 graph-card 确认其与客户、拜访的关系；这是“SQLite 画像结果 + 图关系查询”。

5. 问：东港内部谁更像支持者？
预期：财务部张丽更像潜在支持者，态度积极，但影响力较低，仍需要被赋能。
实现：查画像结果、graph-card 和经营建议中的联系人判断；这是“画像抽取 + 图谱解释”。

6. 问：东港对时间和报价有什么明确要求？
预期：客户希望下周三前拿到初步方案和报价，且最好尽快明确实施方案、报价拆分和服务承诺。
实现：查 `meetingAssistance.actions`、章节摘要和经营建议；这是“行动项抽取 + 文档事实”。

7. 问：东港对实施周期和成本的顾虑是什么？
预期：客户对实施周期和成本比较敏感，已有讨论围绕 50 人天展开，建议方案应优化到不超过 40 人天并清晰拆分实施费与年度服务费。
实现：查经营建议 markdown 与录音摘要；这是“文档检索 + 规则化答案拼装”。

8. 问：东港对我们最大的信任问题是什么？
预期：主要是不满历史 ES 运维表现，包括合同审批问题长期未闭环、安全漏洞暴露、补丁更新不及时、人员变动没有强制通报等。
实现：查 `questionsAnsweringSummary`、`meetingAssistance.actions`、经营建议；这是“文档事实融合”，不是向量推理。

9. 问：东港现在已经记录了什么商机信息？
预期：当前线程里已经确认的意向产品是“轻云、融合中心”，已保存金额为 10 万元。
实现：优先查 `chat_messages` 中的成功状态卡或 Mongo 商机对象；这是“SQLite 精确查询”，属于最稳定的一类问题。

10. 问：如果用户问“东港预算有多少钱”，理想答案应该是什么？
预期：当前资料并没有确认东港的总预算金额；目前只能确认已录入的意向金额为 10 万元，同时预算审批链和最终经济决策人仍未补齐，不能把 10 万元等同于项目总预算。
实现：先查结构化商机金额，再查经营建议里的“预算审批链缺失”；这是“结构化精确查询 + 缺口判断”。这类题必须支持“不知道但说明已知边界”。

## Besmei Sample Questions
说明：这些问题同时覆盖贝斯美的企业研究事实和当前拜访任务上下文，适合通用查询助手的典型能力展示。

预期：核心战略是“单品种极致深耕 + 副产物横向增值”，并以“1+3”路线从二甲戊灵延展到三条新品种线。

4. 问：贝斯美的第二增长曲线是什么？
预期：第二增长曲线是碳五新材料，核心是铜陵基地戊酮系列绿色新材料项目。

6. 问：当前贝斯美这次拜访主要在谈什么需求？
预期：主要在谈金蝶云之家协同办公与 ERP 一体化，重点关注替换钉钉、费用报销、研发项目管理、海外多语言适配和统一门户能力。
实现：查听悟 `paragraphSummary`、`keywords`、`autoChapters`；这是“摘要抽取 + 关键词检索”。

7. 问：贝斯美当前项目阶段是什么？
预期：处于需求初步探索与方案评估的早期阶段。
实现：查经营建议结果或结构化分析字段；这是“结构化精确查询”。

8. 问：贝斯美当前最关键的客户联系人是谁？
预期：当前识别出的关键参与人是财务沈总，影响力高、态度谨慎，关注审批、权限和合规。
实现：查 `meeting_profile_results`、graph-card 与联系人对象；这是“SQLite 画像结果 + 图关系解释”。

9. 问：贝斯美当前最核心的推进障碍是什么？
预期：最大障碍不是兴趣不足，而是决策链信息缺失，同时客户对迁移成本、技术适配、组织架构复杂性、历史数据迁移和海外合规都有明显顾虑。
实现：查经营建议 + 拜访摘要；这是“文档融合 + 缺口识别”。

10. 问：贝斯美当前已经沉淀了什么商机意向？
预期：当前线程已保存的意向产品是“轻云、融合中心、报表秀秀”，金额为 30 万元；但最终拍板人和完整预算审批人仍未确认。
实现：先查 task-status-card 或 Mongo 商机，再补充经营建议中的缺口信息；这是“结构化精确查询 + 文档补充”。

## Query Answer Contract
- 每个答案都建议固定输出 4 段：
  1. 直接答案
  2. 证据来源
  3. 当前未知项
  4. 建议下一问
- 对东港这类“预算未确认”的问题，系统应优先输出“不知道但当前已确认什么”，不能为了顺畅对话臆造数字。
- 对贝斯美这类“企业事实 + 当前任务”混合问题，应先回答企业静态事实，再补当前线程动态状态，避免把研究报告和当前销售阶段混为一谈。

## Acceptance
- 在东港已完成任务线程中输入“东港预算有多少钱”，系统必须回答“总预算未知，但当前已录入意向金额 10 万元”，并指出仍缺预算审批链。
- 在贝斯美线程中输入“贝斯美现在最关键的人是谁”，系统应返回“财务沈总，高影响力、谨慎”，并能引用画像来源。
- 在新线程中输入“贝斯美的第二增长曲线是什么”，系统应直接从研究资料回答，不要求先上传录音。
- 在新线程中输入“东港这次最该推进什么动作”，系统应从经营建议里返回明确下一步，而不是要求重新上传音频。
- 当底层数据缺失或文件路径失效时，系统要回退到其他证据源，并明确说明“依据当前线程记录/经营建议判断”。
